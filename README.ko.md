# Android Also Could Fold

[English](README.md) | **한국어**

**One UI는 그대로. 접고 펼치는 순간만 더 부드럽게.**

Galaxy Z Fold의 물리적인 접힘·펼침 전환을 위한 실험적인 Android 앱입니다.
One UI를 유지하면서 내장 로컬 ADB 클라이언트로 compositor를 제어합니다.
0.4.0에는 **V2: 커버 캡처 + 블랙 그라디언트**를 추가했으며, 앱의 스위치로
기존 **V1 실시간 블러**를 선택할 수 있습니다.

## 동작

| 모드 | 커버 화면 | 내부 화면 |
| --- | --- | --- |
| **V2 · 기본, 실험 기능** | 움직임 시작 시 메모리에 한 장 캡처. 검은 그라디언트가 오른쪽에서 들어온 뒤 펼칠수록 오른쪽 밖으로 이동하며 디졸브하고, 캡처도 실제 화면으로 디졸브 | 왼쪽 절반을 캡처해 가운데 접힘선을 고정하고, 닫을수록 바깥 왼쪽이 후퇴하며 펼칠수록 돌아옴 |
| **V1 · 실시간 블러** | 펼칠 때 오른쪽이 강한 블러 | 왼쪽 절반에 바깥쪽이 강한 블러 |

앱의 **V2 · 캡처 + 블랙 그라디언트**를 끄면 V1으로 돌아갑니다.
효과가 켜져 있을 때 모드를 바꾸면 엔진을 다시 시작합니다.

- 전체 효과 강도 **50–150%** 조절.
- USB 비교 시험에서 추가 테두리 블러만 끄려면 `run --v2` 명령에 `--no-edge-blur`를 추가합니다. 앱 설정에는 영향을 주지 않습니다.
- 원근 캡처의 사선 경계에 안티앨리어싱을 적용하고 이미지 샘플링 필터링을 유지합니다(0.4.12).
- V2는 변형된 화면의 테두리와 검은 배경 경계의 블러를 더 강하게 적용합니다(0.4.11).
  화면 안쪽의 기존 그라디언트는 유지하고, 경계 블러는 움직이는 형태를 따라 함께 해제됩니다.
- 빈 캡처나 보호 레이어·권한 거절은 잠금 해제 중에도 실제 화면의 마스크·블러로
  대체합니다. 이런 일시적 캡처 불가 상태로 엔진을 종료하지 않습니다(0.4.10).
- 커버에서 내부로 전환할 때 직전 후퇴량을 이어받습니다. 완전 펼침 신호가 오면
  140ms 안에 내부 왼쪽을 정확히 평평하게 맞춰 잔여 원근과 블러를 없앱니다(0.4.9).
- V2 원근 효과 위에도 시스템 그라디언트 블러를 적용합니다. 커버는 오른쪽,
  내부 왼쪽 절반은 바깥쪽이 강합니다. 같은 상대 후퇴 진행도에 따라 반경이 변하고,
  내부를 펼쳐 평평해질수록 약해집니다. 잠금 화면의 캡처·마스크 방식 모두 적용하며
  정지 후 원근 효과와 함께 사라집니다. 결합 효과의 실물 조정은 확인이 필요합니다.
- 마지막 움직임 감지 후 **1.5초 정지 → 420ms 동안 자연스럽게 해제**. V2의 캡처 화면도 함께 사라집니다.
- 센서로 확인되는 역방향 움직임에서도 부드럽게 해제.
- 꺼진 화면/AOD에서는 효과 없음. 잠금 화면도 보호 영역을 제외한 캡처를 시도하며, 차단되거나 비어 있으면 실제 화면에 검은 원근 마스크를 표시.
- 설정·페어링 인증키 저장, 연결 유지 서비스, 알림의 중지 버튼 유지.

0.4.7은 커버 캡처의 왼쪽 변을 고정하고 오른쪽 변만 뒤로 줄여
검은 배경 위에 사다리꼴 원근 효과를 만듭니다. 검은 배경은 해제 시점까지 유지합니다.
내부는 왼쪽 절반에 반대로 적용해 가운데 접힘선을 고정합니다. 잠금 화면도
보안·보호 콘텐츠를 제외한 캡처를 시도합니다. 차단되거나 비어 있으면 투영된 형태
바깥을 검은 마스크로 가립니다. 이 대체 방식은 보호된 실제 화면을 변형하지 않습니다. 사용자 시점 추적이나
연속 실측 힌지 각도가 없는 추정 기반 연출이며, 실제 공간 고정은 아닙니다.
V2는 접힘이 감지된 뒤 약 50Hz 자이로의 세로축 상대 회전량으로 커버와 내부 왼쪽 후퇴를
움직입니다. 시간만으로 후퇴를 진행하지 않고, 약 1.5도 역회전 추정 시 해제합니다.
**실측 힌지 각도는 아니며**, 기기 전체를 돌려도 추정값이 변할 수 있습니다.
최신 자이로 값이 없으면 거친 힌지 단계와 고정된 초기 효과로 돌아갑니다.
실물에서의 조정 결과는 아직 확인이 필요합니다.

V2 캡처는 메모리에 잠깐 보관하며 파일 저장·업로드하지 않습니다. 보호된 콘텐츠는
캡처에서 제외되며 해당 영역이 비어 보일 수 있습니다. 캡처가 표시되는 동안 화면은
잠시 정지하지만 터치는 실제 앱으로 전달됩니다. V2의 캡처, 회전, 패널 전환,
실제 화면 모습은 아직 기기 검증이 필요합니다.

## 지원 범위

기존 블러 엔진의 실제 검증 기기는 **Galaxy Z Fold7 SM-F966N / Android 16**입니다.
다른 모델은 실행을 차단하며, 다른 지역의 Fold7 모델도 아직 지원하지 않습니다. Samsung의 비공개 SurfaceControl API에
의존하므로 One UI 업데이트 후 호환성 확인이 필요합니다.

공개 힌지 센서는 이 기기에서 주로 **0 / 90 / 180도**만 전달합니다.
V2의 초기 감지는 300ms 동안 이어지는 신호를 한 번 확인합니다. V1은 기존의
두 번째 신호 확인을 유지합니다. 실제 힌지 변화와 진행 중인 커버→내부 전환에는
새 확인 대기를 추가하지 않습니다. 센서 전달·폴링·캡처 시간이 더해지므로 실제
움직임부터 화면 표시까지 정확히 300ms를 보장하지는 않습니다. 캡처는 최대 300ms
기다린 뒤 라이브 마스크로 대체하고 늦은 결과는 폐기합니다. 정지 해제는 기존 1.5초입니다.

초기 움직임은 `dumpsys sensorservice`의 vendor 이벤트 시각으로 추정하며,
숨겨진 연속 각도 값을 읽는 방식은 아닙니다. 아주 느린 움직임이나 작은 역회전은
구분하지 못할 수 있습니다. 켜진 화면에서 V2는 최대 10Hz, V1은 4Hz 진단 폴링을 사용하며 장시간 배터리
영향은 아직 측정하지 않았습니다.

[통합 앱 설정](#하나의-앱으로-설정하기-041)을 사용하세요. 두 방식 모두 루팅은 필요 없습니다.

## 앱 설치 없이 먼저 체험하기

**Fold Transition APK와 Shizuku를 설치하지 않고도 V1 블러 효과를 시험할 수 있습니다.**
PC에서 ADB로 임시 엔진을 실행하는 방식이며, 기본 **10분 후 자동 종료**됩니다.
루팅이나 Wi-Fi 페어링은 필요하지 않습니다.

PC에 Python 3, JDK 17 이상, Android SDK Platform 36 / Build Tools 36.0.0 /
Platform Tools를 준비하세요. 휴대폰에서 **개발자 옵션 → USB 디버깅**을 켜고,
USB 데이터 케이블로 연결한 뒤 신뢰하는 PC의 디버깅 허용 창을 승인합니다.

저장소 루트에서 실행합니다. `adb`가 PATH에 없으면 SDK의 `platform-tools/adb`
경로를 사용하세요. Python 도구는 `JAVA_HOME`과 `ANDROID_SDK_ROOT`를 읽으며,
macOS에서는 Android Studio JDK와 기본 Android SDK 경로를 사용합니다.
그 외 환경에서는 두 변수를 직접 설정하세요. Windows 실행은 아직 검증하지 않았습니다.

```sh
adb devices -l
adb shell getprop ro.product.model
python3 tools/fold-system.py run --seconds 600 --early
```

`run`이 빌드와 테스트를 수행하고 DEX를 전송한 뒤 실행합니다. APK 설치는 없지만,
기기의 `/data/local/tmp`에 실행 파일과 잠금 파일은 생성됩니다. 지원 기기는 위에
명시한 **SM-F966N**이며, 여러 기기가 연결되었다면 ADB에는 `-s SERIAL`,
Python 명령에는 `--serial SERIAL`을 추가하세요.

`READY`가 나오면 커버·내부 화면·켜진 잠금 화면에서 천천히 접었다 펼쳐보세요.
1.5초 멈추면 블러가 부드럽게 사라집니다. `--early`는 움직임 시작을 추정하는
옵션입니다. 이를 빼면 공개 각도 센서만 사용하므로 시작이 늦을 수 있습니다.

- 시험 중에는 실행 터미널과 USB 연결을 유지하세요. 연결을 끊은 뒤의 지속 동작은 보장하지 않습니다.
- **앱 방식이 켜져 있다면 먼저 앱이나 알림에서 효과를 끄세요.** 두 방식은 동시에 실행하지 않습니다.
- 시간을 바꾸려면 `--seconds`에 1–3600을 지정합니다. 재부팅 후 자동으로 실행되지는 않습니다.
- 기본 V1 체험에는 캡처가 없습니다. `--v2`를 추가하면 메모리 캡처·블랙 그라디언트 실험 모드를 사용합니다. 두 모드 모두 화면을 파일로 저장하거나 업로드하지 않습니다.

10분 전에 끝내려면 다른 터미널에서 실행합니다.

```sh
python3 tools/fold-system.py stop
```

이 명령은 **ADB 임시 엔진만** 중지합니다. 앱 엔진은 앱이나 알림에서 끕니다.
Ctrl+C나 USB 분리만으로 종료됐다고 판단하지 말고, 필요하면 다시 연결해 위 명령으로
중지하세요. 자동 종료 후 전송된 DEX 파일은 남을 수 있지만 자동 실행되지는 않습니다.

상시 사용과 강도 조절 UI가 필요하면 아래 앱 방식을 사용하세요.
에이전트가 실행을 도울 때의 절차와 사용자 안내 문구는 [AGENTS.md](AGENTS.md)에 있습니다.

## 하나의 앱으로 설정하기 (0.4.13)

**이제 Shizuku 설치가 필요 없습니다.** APK 안에 무선 ADB 페어링, 엔진 시작,
재연결 기능을 넣었습니다. One UI를 유지하며 새로운 V2와 기존 V1 블러를 선택할 수 있습니다.
새 연결 방식은 실험 단계입니다. 상시 사용에 앞서 위 검증 상태를 확인하세요.

1. Shizuku 버전에서 업데이트한다면 **기존 앱의 효과를 끈 뒤 설치**하세요.
   ADB 임시 시험도 중지하세요. 엔진들이 같은 잠금 파일을 사용합니다.
2. [Debug APK를 빌드](#빌드와-검증)해 설치하고 **Fold Transition**을 연 뒤 알림을 허용합니다.
3. 신뢰하는 Wi-Fi에 연결하고 **개발자 옵션 → 무선 디버깅**을 켭니다.
4. 앱의 **최초 연결 설정**을 누릅니다. Android 설정의 **페어링 코드로 기기 페어링**
   창을 열고, 창을 닫지 않은 상태에서 **Fold Transition 알림**에 6자리 코드를 입력합니다.
5. 페어링이 완료되면 앱으로 돌아와 V2 또는 V1을 선택한 뒤 **효과 켜기**를 누릅니다.
   **효과 끄기** 또는 알림의 **끄기**로 중지합니다.

페어링 알림은 10분 동안 유지됩니다. **Fold Transition 최초 연결** 알림을 펼치면
**코드 입력** 버튼이 나옵니다. 시간이 지났거나 APK 업데이트로 설정이 중단됐다면
앱에서 **최초 연결 설정**을 다시 누르세요.

현재 UI는 한국어입니다. 페어링 포트 자동 검색이나 알림을 사용할 수 없다면 분할 화면에서
Android 코드 창을 유지한 채 앱의 **포트와 코드 직접 입력**을 사용하세요.
코드 창의 페어링 포트는 무선 디버깅 기본 화면의 연결 포트와 다릅니다.
직접 입력은 **페어링만** 돕습니다. 엔진을 시작할 때는 이 기기의 연결 포트가 자동으로
검색되어야 합니다. 연결 포트 직접 입력 기능은 아직 없습니다.

### 설정이 진행되지 않을 때

- **코드 입력 알림이 없음:** Android 설정을 열기 전에 Fold Transition의 **최초 연결 설정**을
  누르세요. 앱 알림과 **최초 연결 · 코드 입력** 알림 카테고리가 모두 허용되어 있는지
  확인하세요. 효과 실행 상태 알림이 아닌 페어링 알림을 펼쳐야 합니다.
- **포트·코드 오류 또는 페어링 실패:** Android 코드 창을 유지하고 현재 표시된 6자리 코드와
  페어링 포트를 사용하세요. 창을 다시 열면 코드와 포트가 바뀔 수 있습니다.
- **페어링 후 무선 디버깅 연결 대기:** Wi-Fi와 무선 디버깅을 확인하세요. 페어링 성공이 곧
  블러 엔진 실행을 뜻하지는 않습니다. 앱에 **실행 중 · 앱 자체 연결**이 표시되어야 합니다.
- **다른 엔진이 실행 중이라는 오류:** 이전 앱 효과나 ADB 임시 시험을 종료한 뒤 효과를
  껐다 켜세요. 잠금 파일을 삭제하지 마세요.

최초 시스템 승인은 필요합니다. APK 통합만으로 shell 권한이 생기지는 않습니다.
앱은 자체 ADB 인증키를 암호화해 저장하고 재연결 때 재사용합니다. PC나 Shizuku의
페어링과는 별개입니다. 앱 데이터 삭제, 데이터를 유지하지 않는 재설치, Android의
ADB 인증 취소·만료 때는 다시 페어링해야 할 수 있습니다.
참고: [Android ADB 문서](https://developer.android.com/tools/adb#wireless-android11-command-line).

## USB 분리와 복구

**USB를 먼저 분리한 뒤** 효과를 켜고 커버·내부·켜진 잠금 화면에서 접었다 펼쳐보세요.
실행 도중 USB를 분리하는 경우도 별도로 확인해야 합니다. Samsung의 ADB 재시작으로
엔진이 끊기면 무선 디버깅이 사용 가능한 동안 저장된 키로 재연결을 시도합니다.
끊김 없는 애니메이션이나 시스템 영구 설치를 보장하는 것은 아닙니다.

앱은 약 5초 주기로 엔진을 확인합니다. 연결 실패 후 재시도 대기는 최대 30초지만,
포트 검색과 연결 시도 시간이 추가되므로 30초 안에 복구된다는 뜻은 아닙니다.
엔진 오류는 화면에 남으며 효과를 껐다 켜서 재시도합니다. 앱 화면을 닫아도 서비스는
유지됩니다. 연결 종료 시 엔진을 정리하도록 구현했으며, 보조 watchdog은 5초마다
확인해 45초 동안 요청이 없으면 엔진을 종료합니다.

켜짐 상태와 강도는 저장됩니다. 부팅·앱 업데이트 후 서비스 복구를 시도하지만
**이 버전은 꺼진 무선 디버깅을 자동으로 켜지 않습니다.** 재부팅 후 Wi-Fi와 무선
디버깅이 사용 가능하고 Android가 백그라운드 실행을 허용해야 합니다. 강제 중지했다면
앱을 다시 여세요. 배터리 제한, 인증 해제, 디버깅 꺼짐, Wi-Fi 끊김으로 복구가
안 될 수 있습니다. 앱 상태를 확인하세요. 인증이 유효하다면 매번 페어링할 필요는 없습니다.

## 빌드와 검증

JDK 17 이상, Android SDK Platform 36, Build Tools 36.0.0이 필요합니다.
Android Studio의 JDK를 사용해도 됩니다. SDK 경로를 `local.properties`의 `sdk.dir`
또는 `ANDROID_HOME`에 지정하세요.

```sh
./gradlew :app:assembleDebug :app:lintDebug
python3 tools/fold-system.py build
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Python 도구는 `JAVA_HOME`, `ANDROID_SDK_ROOT` 환경변수를 지원합니다.
macOS에서는 Android Studio와 기본 Android SDK 경로를 사용합니다.
Debug APK는 개발용 서명입니다. 배포용 release APK는 별도 서명이 필요합니다.
`adb install -r`로 기존 앱을 업데이트하려면 같은 서명 키를 유지해야 합니다.
서명이 다른 APK는 기존 앱에 덮어쓸 수 없으며, 앱을 삭제하면 설정과 페어링 인증키도
사라집니다.

기기에서 실행하는 인증키 테스트는 로컬 빌드·lint와 별도입니다.
실행 전 [검증 기록](docs/LOCAL_ADB_APP.md#validation)을 참고하세요.

## 구성

| 경로 | 역할 |
| --- | --- |
| `app/` | 설정 UI, 로컬 ADB 페어링·연결, foreground service, 복구 |
| `system/` | V1 블러·V2 캡처 렌더러, 접힘 상태 머신, 그라디언트, JVM 테스트 |
| `tools/` | 독립 ADB 시험과 센서 진단 |
| `third_party/` | 내장 로컬 ADB 라이브러리, 출처와 라이선스 |
| `legacy/` | 빌드에서 제외된 초기 화면 캡처·Shizuku 구현 |
| `docs/` | 기기 조사와 구현 기록 |

로컬 ADB 소켓을 위해 Android의 `INTERNET` 권한을 사용하고 mDNS로 이 기기의
디버깅 포트를 찾습니다. 실제 ADB 연결 대상은 `127.0.0.1`뿐이며 검색된 다른 기기에
연결하지 않습니다. 분석 SDK와 접근성 서비스는 없습니다. V2는 MediaProjection 없이
shell compositor API로 켜진 패널을 캡처하며 잠금 화면에서도 보안·보호 콘텐츠는
제외합니다. 내부 패널은 캡처 직후 왼쪽 절반만 보관합니다. 센서 진단과 임시 캡처는 기기
내부에서만 처리합니다. 개인 인증키는 Android Keystore로 암호화하며 백업에서 제외합니다.

구현과 검증 범위는 [통합 연결 설계](docs/LOCAL_ADB_APP.md)를 참고하세요.
